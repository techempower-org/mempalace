# Fork-change entries whose squash commit cannot be identified (#472).
#
# scripts/check-docs.sh requires every entry's `commit:` to be an ANCESTOR of
# HEAD -- resolving is not enough, because a dangling branch commit resolves
# fine (locally, and in GitHub's unreachable-object store) until it is
# garbage-collected. That is how 13 entries came to point at commits
# unreachable from main while every check stayed green.
#
# The entries below predate any post-merge resolution step. Their change IS on
# main; the commit carrying it can no longer be named, because the squash
# subject was rewritten at merge and the branch commit is unreachable.
#
# Counts, measured: 27 entries were non-ancestors when this change started (a
# further 13 were fixed earlier, in #475). scripts/maintain-fork-changes.py
# resolved 3 of the 27 by exact subject match and REFUSED the other 24 rather
# than guess, which is its documented contract.
#
# They are recorded here instead of being given a plausible sha, because a
# wrong reference passes every check and misleads a reader, while this file is
# a visible diff the moment anyone adds a line. Adding an id here is a
# deliberate, reviewable act -- NOT a place to park a stale sha from work you
# just did. Fixing one means finding its real commit and deleting its line.
#
# A looser token-similarity pass would recover roughly 8 of these (subjects
# reworded at merge, e.g. "add why + tunnels ..." -> "why + tunnels ..."). It
# was deliberately not applied: the tool refuses ambiguous matches by design,
# and hand-applying matches it rejects in the same change would undercut that
# contract. Worth doing as its own reviewed pass.
#
# Format: `<entry id> <known-bad sha>` per line. Blank lines and # comments
# ignored; an id with no sha is a hard error.
#
# The sha is part of the KEY, not a note. Keyed on the id alone this file would
# grant an entry a permanent exemption instead of recording one known-bad sha:
# its `commit:` could later be edited to anything -- including a plausible
# WRONG sha, which is a real ancestor and so passes every check -- and never be
# looked at again. Pinning the sha makes a resolved or altered entry fail the
# check until its line is removed, which is the prompt we want.
